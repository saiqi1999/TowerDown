# 《深处的文明》GDD v0.2

> **文档类型**：核心玩法 GDD / 系统设计基线  
> **版本**：v0.2  
> **当前阶段**：原型前期  
> **核心目标**：定义“移动文明 + 地下层探索 + 自动战斗 + Build 构筑 + 文明进化”的完整游戏骨架，作为后续原型、数值、美术与程序实现的共同依据。

---

# 1. 游戏概述

## 1.1 游戏名称

**《深处的文明》**

## 1.2 类型

**Roguelite × 城市经营 × 自动战斗 × Build 构筑 × 文明进化**

## 1.3 核心幻想

玩家经营一座建立在巨大钻井平台上的移动文明。

整座村庄 / 城市会随着钻井平台不断向世界深处移动。每抵达新的地下层级，周围会生成新的资源点、中立怪物营地和新的风险。

玩家需要：

- 规划资源获取顺序；
- 判断哪些怪物营地值得攻打；
- 建设与升级城市；
- 培养战士；
- 构筑战士 Build、防御塔 Build、研究 Build 与文明被动；
- 判断当前层还值不值得继续停留；
- 在风险和收益之间做取舍；
- 最终带着完整文明面对深处 Boss。

---

# 2. 核心体验目标

## 2.1 Build 爆炸

游戏最核心的爽感来自：

> 玩家通过战士、技能、建筑、研究、被动、文明等级和资源效率之间的巧妙组合，找到多个数值乘区，使整个文明从“勉强运转”逐渐进入“体系成型”，最后产生极强的滚雪球与战斗表现。

核心不是单纯堆高数值，而是：

```text
战士种类
×
战士技能
×
全局被动
×
建筑加成
×
防御塔体系
×
文明研究
×
资源效率
×
特殊联动
```

优秀 Build 应该让玩家产生：

> “原来这几个系统放在一起会这么强。”

## 2.2 文明进化

玩家成长的主体不是某一个英雄，而是整个文明。

文明等级提升后会解锁：

- 新建筑蓝图；
- 新研究项目；
- 新战士种类；
- 新技能池；
- 新被动池；
- 更高级的经济与防御体系。

玩家应明显感受到：

```text
原始聚落
→ 稳定村庄
→ 成熟城镇
→ 工业化 / 高科技文明
→ 深层文明
```

每一次时代进化都应改变玩法空间，而不仅是“所有属性 +10%”。

## 2.3 深层探索的风险收益

每一层都不是纯粹清图。

玩家始终在决定：

> “我要不要为了更肥沃的资源，去承担更大的战斗风险？”

高收益资源通常被更危险的怪物营地控制。

因此：

```text
安全资源
= 收益稳定但有限

危险营地
= 更高战斗风险
= 更肥沃 / 更高等级的资源区
```

中后期玩家不一定有能力吃下所有资源。

**放弃资源，本身就是正确决策的一部分。**

```text
    ↓

```

# 4. 单层结构

## 4.1 新层初始化

每次进入新层时生成：

- 基础地形；
- 普通资源点；
- 肥沃资源点；
- 中立怪物营地；
- 特殊营地；
- 潜在高风险资源区；
- 当前层危险等级；
- 当前层资源丰度。

钻井平台和已有文明整体进入新层。

以下内容全部保留：

- 已建建筑；
- 已有战士；
- 当前蓝图；
- 当前科技；
- 当前被动；
- 当前 Build；
- 文明等级。

# 5. 地图资源与怪物营地

## 5.1 普通资源点

普通资源点可以直接插旗进行采集。

特点：

- 风险较低；
- 收益有限；
- 适合保证基础经济；
- 是弱 Build 或状态不佳时的安全选择。

## 5.2 肥沃资源点

部分高价值资源区不会直接开放。

这些资源点由中立怪物营地控制。

结构：

```text
怪物营地
    ↓
守护
    ↓
肥沃资源区
```

玩家必须先：

```text
插旗攻击怪物营地
↓
战士前往作战
↓
清除营地
↓
资源点解锁
↓
才能插旗采集
```

肥沃资源区应体现明显优势，例如：

- 更高采集效率；
- 更高单位产出；
- 更稀有资源；
- 更高知识产量；
- 更高黄金收益；
- 多种资源混合产出；
- 特殊事件 / 遗迹奖励。

## 5.3 风险与收益

营地危险程度与资源价值正相关。

设计目标：

```text
更危险的营地
≈
更值得争夺的资源
```

玩家不应该自然清光整张地图。

特别是在中期以后：

> 正确决策往往是只打自己 Build 能稳定处理的营地，主动放弃部分资源。

---

# 6. 插旗与统一指挥系统

## 6.1 玩家不直接操作单位

本作避免高微操 RTS。

玩家主要通过：

> **插旗**

向整个战士群体下达战略目标。

可插旗对象包括：

- 普通资源点；
- 怪物营地；
- 已解锁资源区；
- 特殊目标。

## 6.2 战士统一指挥

所有战士均属于同一个统一战斗群。

玩家不能：

- 指定“3 个战士去左边”；
- 指定“5 个弓手去右边”；
- 手工拆分部队人数；
- 高频控制单个单位。

即：

```text
全部战士
    ↓
统一接受当前战略目标
```

不同兵种会在内部自动发挥各自特长。

这样玩家关注的是：

```text
打不打
先打谁
什么时候打
当前 Build 能不能打
```

而不是：

```text
具体哪个单位站哪里
```

---

# 7. 战士系统

## 7.1 战士核心定位

所有战士的共同核心价值是：

- 战斗力；
- 生存能力；
- 与其他系统的搭配能力；
- 对当前 Build 的贡献。

不同战士之间的区别主要体现在：

- 攻击距离；
- 攻击速度；
- 单体 / 范围；
- 生存能力；
- 控制能力；
- Buff / Debuff；
- 特殊触发；
- 与建筑 / 技能 / 被动的联动。

## 7.2 战士种类

示例：

```text
近战战士
- 高生存
- 顶前排
- 适合防御型联动

弓手
- 高攻速
- 适合暴击 / 触发 Build

重装战士
- 极高耐久
- 适合保护其他单位

工程兵
- 可能强化防御塔或建筑

特殊兵种
- 随文明等级解锁
```

重点不是形成传统“坦克 / 输出 / 治疗”的硬性职业框架，而是：

> 每种战士都能成为某些 Build 的关键组件。

---

# 8. 战士死亡与复活

## 8.1 死亡机制

战士在战斗中可以死亡。

死亡后：

> **当前回合不能再次参与行动。**

## 8.2 复活机制

死亡战士需要等待：

```text
下一个回合
```

才能复活 / 恢复参战资格。

因此战斗损失不仅仅是生命值损失，还会造成：

> **行动节奏损失。**

例如：

```text
本回合强行挑战高危营地
↓
大量战士死亡
↓
虽然赢下营地
↓
但这一回合剩余探索能力大幅下降
↓
下一回合才能恢复完整战力
```

## 8.3 战斗失败的意义

失败不一定直接导致 Game Over。

更常见的代价是：

- 浪费一个回合；
- 战士集体进入复活等待；
- 错失资源收益；
- 当前层开发效率下降；
- 被迫放弃其他资源点；
- 可能提前选择下潜。

# 9. 资源系统

基础资源共五种：

| 资源 | 主要用途 |
|---|---|
| 食物 | 战士维持、恢复、人口相关系统 |
| 木头 | 基础建筑、建造、修复 |
| 石头 | 高级建筑、防御工事 |
| 黄金 | 高价值建设、特殊消费、高级经济 |
| 知识 | 研究、蓝图、技能、文明升级 |

资源来源：

```text
地图采集
+
建筑每回合产出
+
怪物奖励
+
研究 / 被动联动
+
特殊事件
```

---

# 10. 建筑系统

建筑分为三大类。

## 10.1 经济建筑

核心：

> 每回合自动产生资源。

例如：

- 农场；
- 伐木场；
- 采石场；
- 金矿 / 商业设施；
- 特殊经济建筑。

高级经济建筑可以参与 Build，例如：

```text
每拥有一个农场
→ 战士最大生命 +X%

每采集一定数量木材
→ 获得额外知识

黄金收入达到阈值
→ 防御塔伤害提升
```

## 10.2 研究建筑

消耗知识产生长期成长。

主要研究类型：

### 蓝图研究

```text
投入知识
↓
等待回合结算
↓
获得建筑蓝图
```

### 技能研究

```text
投入知识
↓
回合结束
↓
随机出现三个技能
↓
三选一
```

### 文明研究

用于推进文明等级。

## 10.3 防御塔建筑

防御塔拥有独立 Build 空间：

- 攻速；
- 射程；
- 暴击；
- 穿透；
- 范围伤害；
- 控制；
- 元素；
- 连锁；
- 触发类效果。

防御塔与战士 Build 可以互相联动。

---

# 11. 技能系统

研究型建筑可以在回合结束时生成：

> **三选一随机技能。**

技能可能强化：

- 某类战士；
- 所有战士；
- 某类防御塔；
- 资源采集；
- 建筑产出；
- 研究效率；
- 特殊触发机制。

示例：

```text
弓手每第 3 次攻击额外射击

近战击杀恢复全体生命

每次获得黄金时
有概率提高下一回合研究效率

防御塔攻击被减速的敌人时暴击率翻倍
```

# 12. 全局被动

全局被动主要来自：

- 过层奖励；
- 特殊事件；
- 文明升级；
- Boss / 精英奖励。

强化范围包括：

## 战士

- 某兵种伤害；
- 攻速；
- 暴击；
- 生存；
- 特殊触发。

## 防御塔

- 塔伤害；
- 射程；
- 攻速；
- 元素效果；
- 连锁效果。

## 资源

- 采集效率；
- 资源点收益；
- 建筑资源产量；
- 特定资源联动。

## 文明

- 研究效率；
- 蓝图品质；
- 三选一质量；
- 文明升级速度；
- 修复效率。

---

# 13. 蓝图系统

建筑并非默认全部开放。

玩家通过：

- 研究；
- 文明升级；
- 过层奖励；
- 特殊事件；
- Boss；

获得建筑蓝图。

蓝图决定：

> 当前这一局文明能构筑什么样的城市。

不同局可能形成完全不同的建筑体系。

---

# 14. 文明等级

文明等级是整局的纵向成长轴。

升级后解锁：

- 更高级蓝图；
- 更高级被动；
- 新战士；
- 新研究项目；
- 新技能池；
- 新经济系统；
- 新防御塔体系。

设计原则：

> 文明等级提升必须明显改变可用策略，而不是单纯增加基础属性。

# 15. 回合系统

游戏采用回合 / 周期驱动。

每个回合中玩家进行：

- 插旗；
- 战斗；
- 采集；
- 建造；
- 修复；
- 研究安排；
- 资源分配。

回合结束时结算：

```text
经济建筑产出
+
研究推进
+
技能研究三选一
+
死亡战士复活
+
部分被动触发
+
文明研究推进
```

战士死亡机制与回合系统直接绑定。

# 16. 中期压力系统

## 16.1 设计目的

前期主要让玩家：

- 理解系统；
- 建立基础经济；
- 找到 Build 方向；
- 获得关键组件。

从中期开始，游戏逐渐施加真正的 Build 检验。

## 16.2 “差 Last Piece”的状态

玩家可能已经拥有：

```text
Build A
+
Build B
+
Build C
```

但仍然缺：

```text
关键技能 / 关键蓝图 / 关键战士 / 关键被动
```

此时 Build 只能处理部分中等风险营地。

而地图上会出现：

```text
高收益资源
↓
被高危营地控制
```

玩家必须接受：

> 当前 Build 不完整，因此拿不到这部分资源。

## 16.3 错误 Build 的代价

如果玩家构筑方向存在明显问题：

- 输出不足；
- 生存不足；
- 联动效率低；
- 资源投入失衡；
- 文明升级过慢；

中期不会立刻 Game Over。

而是逐渐产生：

```text
打不过部分营地
↓
放弃肥沃资源
↓
经济弱于理想状态
↓
后续 Build 进一步受到限制
```

形成渐进式压力。

## 16.4 设计目标

中期难度不应是：

> “你 Build 错了，所以马上死。”

而应是：

> “你的 Build 不够好，因此必须舍弃部分地图价值。”

这是本作的重要策略空间。

# 17. 难度系统

不同难度主要调整：

## 战斗压力

- 怪物基础属性；
- 营地规模；
- 精英比例；
- 营地特殊机制。

## 资源压力

- 普通资源丰度；
- 肥沃资源收益；
- 高价值资源被营地保护的比例。

## Build 容错

低难度：

```text
不完整 Build
仍可处理大部分资源区
```

高难度：

```text
中期开始
必须形成较完整体系
否则会持续失去高价值资源
```

## 17.1 难度设计原则

难度越高，不应单纯变成：

```text
怪物 HP × 300%
```

而应该更明显体现：

> **资源获取权与 Build 质量之间的关系。**

高难度的核心压力：

```text
正确 Build
→ 可以争夺更多地图价值

错误 / 不完整 Build
→ 被迫放弃更多资源
```

---

# 18. 钻井平台充能

击杀一定数量的怪物后：

```text
钻井能源不断积累
↓
达到阈值
↓
平台充能完成
```

此后解锁：

> **下潜**

但不会强制离开。

---

# 19. 留层还是下潜

平台充能后，玩家面临核心决策：

```text
这一层还有肥沃资源
但高风险营地还没打

↓

继续留下？

还是

保存状态直接下潜？
```

继续停留可能获得：

- 更多资源；
- 更多黄金；
- 更多知识；
- 更完整 Build。

也可能：

- 战士大量死亡；
- 浪费回合；
- 修复成本上升；
- 资源换血不划算。

---

# 20. 过层奖励

进入下一层前提供奖励选择。

主要包括：

## 新战士

加入当前文明。

## 全局被动

强化当前 Build。

## 建筑蓝图

扩展城市构筑空间。

后续也可考虑：

- 特殊遗物；
- 文明政策；
- 稀有研究项目。

# 22. Boss 战

Boss 应检验整个文明，而不是单纯战士 DPS。

Boss 战需要综合利用：

- 战士 Build；
- 防御塔 Build；
- 建筑体系；
- 经济储备；
- 文明科技；
- 修复能力；
- 技能联动；
- 全局被动。

最终目标：

> 让玩家看到自己几十分钟构筑出的文明全面运转，并以明显“超模”的 Build 爆发击败最终 Boss。

---

# 23. 设计支柱

## 23.1 整个文明是主角

不是英雄冒险，而是：

> 一个文明不断向地下移动。

## 23.2 少微操，多战略

玩家控制：

- 目标；
- 风险；
- 投资；
- Build；
- 资源分配。

而不是直接控制每个单位。

## 23.3 风险与资源绑定

更好的资源应该意味着：

> 更强的怪物营地。

地图不能只是“全部清完”。

## 23.4 允许放弃资源

尤其进入中期以后：

> 没拿到某个资源区并不等于失败。

这是玩家判断 Build 强弱的重要反馈。

## 23.5 Build 应允许失控

优秀 Build 后期应该明显超出线性成长：

- 极高攻击速度；
- 连锁攻击；
- 巨量资源；
- 技能触发循环；
- 战士和防御塔互相强化；
- 多系统形成乘区。

---

# 24. Build 结构

整体 Build 可以理解为：

```text
                    文明等级
                        ↓

        ┌───────────────┼───────────────┐
        ↓               ↓               ↓

     战士体系        建筑体系        研究体系
        ↓               ↓               ↓
     兵种技能        经济/防御        技能/科技
        └───────────────┼───────────────┘
                        ↓
                     全局被动
                        ↓
                     数值乘区
                        ↓
                    最终 Build
```

设计重点：

> 系统之间应尽量存在横向联动，而不是各玩各的。

---

# 25. 失败与挫折层级

本作尽量避免只有：

```text
成功
/
Game Over
```

而是建立多个失败层级：

### 轻度失败

- 某资源点未拿到；
- 某营地暂时打不过。

### 中度失败

- 大量战士死亡；
- 损失一个回合；
- 被迫放弃多个资源区。

### 重度失败

- Build 长时间无法提升；
- 当前层开发效率严重下降；
- 提前下潜。

### 最终失败

- 无法应对关键层 / Boss；
- 本局结束。

这样游戏能给玩家更连续的 Build 反馈。

# 26. 第一版原型路线

## P0：地图底层

```text
MapData
→
静态地图正确显示
```

当前正在进行。

## P1：最小资源循环

实现：

```text
钻井平台
+
一个资源点
+
一组战士
+
插旗
+
自动移动
+
采集木头
```

目标：

> 验证“插旗 → 战士响应 → 获得资源”是否直观。

## P2：营地与资源风险

增加：

```text
怪物营地
+
营地守护肥沃资源
+
战士自动战斗
+
击败后解锁资源
+
死亡下一回合复活
```

这是第一版非常关键的玩法验证。

目标：

> 验证“打营地换资源权”是否有策略性。

## P3：城市经营

增加：

- 食物；
- 木头；
- 石头；
- 黄金；
- 知识；
- 经济建筑；
- 修复；
- 回合结算。

## P4：Build

增加：

- 技能三选一；
- 战士类型；
- 全局被动；
- 防御塔；
- 蓝图系统。

## P5：完整单层

增加：

```text
钻机充能
+
继续停留
/
主动下潜
+
刷新下一层
```

此时形成第一个完整 Vertical Slice。

## P6：文明进化

加入：

- 文明等级；
- 新时代；
- 新战士；
- 新建筑；
- 新技能池。

## P7：中期压力

加入：

- 高风险营地；
- 肥沃资源；
- Build 强度门槛；
- 难度调节；
- 主动放弃资源的策略空间。

## P8：Boss

完成完整一局流程。

# 27. 首个 Vertical Slice 的目标体验

最小完整体验应做到：

```text
进入地下层
↓
观察资源
↓
插旗采集
↓
发现肥沃资源被怪物守护
↓
插旗攻击
↓
战士自动战斗
↓
部分战士死亡
↓
下一回合复活
↓
占领资源点
↓
获得更多资源
↓
建设 / 研究
↓
Build 变强
↓
击杀足够敌人
↓
钻机充能
↓
判断是否继续留层
↓
主动下潜
↓
获得奖励
↓
进入下一层
```

如果这一循环本身好玩，游戏的主体就成立。

# 28. 当前需要后续继续明确的问题

以下内容在 v0.2 暂时不锁死：

1. 一个“回合”具体持续多久；
2. 插旗是否一次只能存在一个；
3. 战士如何决定战斗站位；
4. 战士复活是否需要资源；
5. 建筑是否占格；
6. 防御塔主要用于营地进攻、基地防守，还是两者都有；
7. 怪物是否会主动进攻基地；
8. 每层地图大小；
9. 每局大约多少层；
10. 文明等级总数；
11. Boss 是否存在多阶段；
12. 资源点是否会耗尽；
13. 玩家是否可以主动撤退正在进行的营地战。

这些问题应在对应 Prototype 被验证后再确定，避免过早设计。
